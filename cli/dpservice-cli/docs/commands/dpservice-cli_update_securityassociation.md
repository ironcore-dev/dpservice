## dpservice-cli update securityassociation

Replace an egress IPsec Security Association, without a gap in the traffic it protects

```
dpservice-cli update securityassociation <--vni> <--spi> <--direction> <--src-underlay> <--dst-underlay> <--new-spi> <--key> <--salt> [flags]
```

### Examples

```
dpservice-cli update securityassociation --vni=100 --spi=43794 --direction=egress --src-underlay=fc00:1:: --dst-underlay=fc00:2:: --new-spi=43795 --key=9c3d0b7e4a1f8256d0e4b39f7c15a862 --salt=5d24c9b1
```

### Options

```
      --algorithm string       Cipher to use (aes-128-gcm or aes-256-gcm). (default "aes-128-gcm")
      --direction string       Direction of the association (egress, the only direction that can be replaced).
      --dst-underlay ip        Destination underlay address of the association. (default invalid IP)
      --esn                    Use extended (64-bit) sequence numbers. Both ends of the tunnel must agree.
  -h, --help                   help for securityassociation
      --key string             Hex-encoded cipher key. The replacement starts a sequence number of its own, so this has to be key material the association has not used before.
      --new-spi uint32         Security Parameter Index the association carries from here on.
      --replay-window uint32   Anti-replay window in packets. An egress association has nothing to check, so only zero, the default, is accepted.
      --salt string            Hex-encoded salt, the implicit part of the nonce.
      --spi uint32             Security Parameter Index the association carries now.
      --src-underlay ip        Source underlay address of the association. (default invalid IP)
      --vni uint32             VNI of the association.
```
